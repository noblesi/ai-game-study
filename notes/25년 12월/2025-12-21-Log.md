## 2025-12-21 AI, 파이썬 공부 로그

### 오늘 한 것
- 데이터 누수/암기 가능성 점검을 위해 **Group Split** 평가를 도입
  - `export_dataset.py`에 `pair_key` 컬럼을 추가하여 (attacker, defender) 조합 단위로 그룹 키 생성
  - `train_baseline.py`에 `--group`, `--group-key` 옵션을 추가해 GroupShuffleSplit 기반 분할 지원
  - Group Split 적용 후, DT/RF가 랜덤 split에서 보였던 “거의 1.0” 성능에서 현실적인 수준으로 하락함을 확인(조합 암기 가능성 시사)
- Group Split에서 split별 라벨 분포 흔들림을 줄이기 위해 **group-stratified** 적용
  - `--group-stratified` 옵션 추가
  - 그룹 라벨(그룹 내 y 다수결)을 사용해 StratifiedShuffleSplit으로 그룹을 샘플링
  - `test_pos_rate(label=1)`를 출력해 split별 라벨 비율이 안정화됨을 확인
- 현재 평가 기준(조합 단위 분리 + 라벨 비율 안정)에서의 best 모델 재확인
  - RF_balanced_subsample이 f1_1(mean) 기준 best로 유지
  - 중요 피처 상위권에서 `ttk_adv`, `dmove_speed`, `a_dps`, `d_ttk_est`, `dps_adv` 등이 반복적으로 등장

### 어려웠던 점 / 체크포인트
- Threshold 튜닝 로직을 어디에 넣어야 하는지 흐름(베스트 모델 선택 → 리포트 저장) 관점에서 위치가 헷갈렸음
  - 해결 방향: `main()`에서 **BEST MODEL / TOP FEATURES 출력 직후 ~ report_path 생성 직전** 구간에 튜닝 블록을 삽입하는 구조로 정리
- Group Split은 “조합 누수”를 줄이지만 split별 라벨 비율이 흔들릴 수 있음
  - `group-stratified`로 테스트셋 양성 비율을 안정화시키고, 이후 모델 비교 신뢰도를 높이는 방향이 적절
