## 2025-12-26 AI, 파이썬 데일리 로그

### 오늘 한 것
- `export_dataset.py` CSV export 파이프라인 점검 및 스키마/필드네임 이슈 해결
  - `csv.DictWriter` 사용 시 `fieldnames`에 없는 키(`pair_key_full`)로 인해 발생한 오류 확인
  - `fieldnames`에 `pair_key_full` 포함되도록 수정/검증하여 export 정상 동작 확인
- `train_baseline.py` 베이스라인 평가 파이프라인 실행 및 비교
  - group split 기준을 `pair_key` vs `pair_key_full`로 바꿔가며 결과 비교
  - `--group-stratified`, `--tune-threshold`, `--rf-grid` 옵션 조합으로 리포트 생성 흐름 검증
  - fixed test 평가에서 `--drop-overlap-groups` 적용 시 “usable test rows 감소 → f1_1=0” 같은 케이스 확인(평가 세팅 영향 파악)
- feature schema(특히 perk one-hot + advantage) 순서 의존성 재확인
  - `BASE_FEATURE_NAMES / BASE_NUM_KEYS`와 `build_features()`에서 `x`를 만드는 순서가 반드시 일치해야 함을 재점검
  - `PERK_IDS`를 CSV 컬럼에서 동적으로 감지 → `rebuild_feature_schema()`로 `FEATURE_NAMES/NUM_KEYS`를 재구성하는 구조 확인
- `Final train + save` 패치 위치/구조 정리
  - `main()` 마지막(리포트 append 후, fixed test eval 전)에 두는 것이 적절하다는 점 확정
  - 기존 저장 블록의 문제점(없는 함수 호출, threshold fallback 0.5 고정, RF grid params 미반영) 식별
  - 해결 방향: `fit_final_estimator()` + `save_bundle()`를 쓰는 방식으로 저장 블록 교체 계획 수립

### 어려웠던 점 / 체크포인트
- **CSV DictWriter는 fieldnames와 row dict의 키가 정확히 일치**해야 함
  - 데이터에는 있는데 fieldnames에 없으면 바로 `ValueError`로 터짐 → 스키마 변경 시 항상 동기화 필요
- **Feature 순서 의존성**
  - 모델 학습에서 “컬럼 이름”이 아니라 “벡터 인덱스”가 의미를 갖기 때문에
  - `build_features()`의 x 구성 순서와 `FEATURE_NAMES` 순서가 어긋나면 학습/해석이 깨짐
- **Group split 설정에 따른 평가 해석**
  - `pair_key_full`은 그룹이 더 잘게 쪼개져 누수 방지가 강해지고,
  - `drop-overlap-groups`까지 켜면 고정 테스트 usable rows가 급감할 수 있음(이 경우 f1이 0으로 떨어질 수 있음)
- **Final save는 “코드 위치”보다 “저장 로직의 일관성”이 더 중요**
  - best/tuned/rf_grid 결과를 저장 단계에서 제대로 재사용(모델/threshold/params)하도록 설계해야 함
