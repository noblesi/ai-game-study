## 2025-11-27 파이썬 공부 로그

### 오늘 한 것
- 유닛 검색 및 선택 기능 구현
  - `search_units(units: List[Unit], keyword)`를 구현하여 이름에 키워드가 포함된 유닛만 필터링
  - 검색 결과를 `(원본 인덱스, Unit 객체)` 형태의 리스트로 반환하도록 설계하여 이후 레벨업/삭제 기능에서 재사용 가능하게 만듦
  - `search_unit_menu_for_select(units: List[Unit])`를 통해 검색어 입력 → 검색 결과 목록 출력 → 번호 선택 → 선택된 유닛의 인덱스를 반환하는 흐름을 완성
  - 검색어 미입력, 검색 결과 없음, 잘못된 번호 입력 등 다양한 예외 상황을 처리하여 입력 흐름 안정화
- 검색 기능을 활용한 레벨업/삭제 메뉴 개선
  - `level_up_unit_menu(units: List[Unit])`에서 등록된 유닛이 없을 때 안내 문구 출력 후 바로 종료하도록 처리
  - `search_unit_menu_for_select`를 통해 선택된 유닛을 가져와 `unit.level_up()` 메서드를 호출하는 방식으로 객체지향적인 레벨업 처리 구현
  - `remove_unit_menu(units: List[Unit])`에서 유닛이 없을 경우 삭제 불가 안내 메시지를 출력하고, 검색 후 선택된 유닛을 `units.pop(selected_index)`로 삭제하는 로직 정리
  - 레벨업/삭제 완료 메시지 출력 형식을 통일하여 사용자 입장에서 결과를 확인하기 쉽게 만듦

### 어려웠던 점
- `for unit in units` 루프에서 `units`와 `unit`을 헷갈리지 않도록 주의해야 했고, `(인덱스, 객체)` 튜플 구조에 익숙해지는 데 시간이 조금 걸렸음
- 화면에 보여주는 번호(1, 2, 3…)와 실제 리스트 인덱스(0부터 시작)를 분리해서 관리하는 흐름이 처음에는 헷갈렸으나, `enumerate`와 `choice_num - 1` 패턴을 통해 정리함
- 검색 로직(순수 함수)과 메뉴 입출력 로직을 분리하는 과정에서, 각 함수가 어디까지 책임져야 하는지(검색만 담당하는 함수 vs 입력/출력까지 담당하는 함수)를 나누어 생각하는 데 시간이 필요했음
