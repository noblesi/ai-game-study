- 시나리오 로더(scenario_loader.py) 수정  
  - ```json 코드블록을 잡는 정규식에 이름 있는 그룹 `(?P<json>...)` 추가  
  - `m.group("json")`로 JSON 본문을 안전하게 파싱하도록 수정  
  - md 파일/JSON 파싱 상태를 확인할 수 있도록 `[DEBUG]` 로그 추가
- duel 시나리오 프리셋 정리  
  - `battle_scenarios_duel.md`를 한 시나리오당 하나의 ```json 블록으로 재구성  
  - Knight vs Goblin, Archer vs Runner 등 5개 1v1 프리셋을 units.json 기반 메타 시나리오로 정리
- 시나리오 메뉴(battle_scenarios_menu) 동작 개선  
  - 시나리오에서 `attacker_name/defender_name` + `attacker_level/defender_level`를 읽어와 units.json 유닛을 찾고, 레벨에 맞게 스탯 보정하는 흐름 구현

  - `print_battle_summary` 대신 multi-trial 요약(승률/평균 시간/평균 HP 등)을 출력하는 전용 포맷으로 교체
- 시나리오 프리셋 기반 실험 수행 및 데이터 축적  
  - duel + swarm 포함 총 9개의 시나리오 프리셋을 각각 1회 실행 (각 200 트라이얼)  
  - 실행 결과를 `logs/scenarios.jsonl`에 `scenario_preset` 로그로 저장
- 시나리오 기반 데이터셋/베이스라인 확인  
  - 로그를 기반으로 작은 규모의 시나리오 전용 데이터셋 생성  
  - `train_baseline.py`로 학습/평가 실행  
  - 입력 행 24개, label 1:0이 12:12로 균형인 상태에서  
    - LR / RF 등이 test_acc=1.0, f1=1.0에 가까운 과적합 성능을 보이는 것을 확인  
  - top features에서 `datk`, `dhp`, `ttk_adv`, `dps_adv` 등이 핵심 피처로 잡히는 것을 확인

### 어려웠던 점 / 체크포인트
- 시나리오 md 포맷 문제
  - 처음에는 하나의 ```json 블록 안에 JSON 객체를 여러 개 나열하고, 마지막 ```를 누락해서 로더가 시나리오를 전혀 인식하지 못하는 문제가 발생  
  - 정규식/그룹 이름 버그(`m.group("json")` vs 캡처 그룹)를 함께 수정하면서, md 포맷을 “한 시나리오 = 한 블록”으로 정리해 해결
- 출력 포맷 혼동
  - multi-trial 요약 dict를 단일 전투 요약용 함수 `print_battle_summary`에 그대로 넘겨서 승자/시간/HP가 전부 0/none으로만 찍히는 문제 발생  
  - multi-tr라이얼용 요약 출력 포맷을 따로 구현해 승률/평균 시간/평균 공격 수 등을 제대로 확인 가능하도록 수정
- 데이터셋 크기와 모델 성능 해석
  - 현재 시나리오 기반 데이터셋 크기가 24행 수준으로 매우 작아, LR/DT/RF가 test_acc=1.0에 도달하는 “과하게 좋은” 결과가 나옴  
  - 이 결과는 모델이 정말로 일반화된 것이 아니라, 데이터가 너무 적어 decision boundary를 거의 완벽히 외운 상태라는 신호로 해석  
  - 추후에는 시나리오 종류(레벨 조합/duel vs swarm)를 확장하고 로그를 더 쌓아서, 보다 현실적인 성능/피처 중요도를 얻는 것이 필요하다는 체크포인트 확보
